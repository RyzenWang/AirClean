# 事故台账

> 目的：每个真实踩过的坑都留下"引入 / 修复 / 本该拦住的层 / 现在拦它的测试"，
> 让同类问题第二次出现时能被机器挡住，而不是靠记性。
> 格式参考 tw93/Mole 的 `docs/incidents.md`（GPL-3.0，仅借鉴组织方式，未复制内容）。

## 怎么记

每条事故一行表格，四个必填项：

| 字段 | 含义 |
| --- | --- |
| 引入 | 哪个版本/提交第一次引入 |
| 修复 | 哪个版本/提交修好 |
| 本该拦住 | 最早能拦住它的层：`写入时` / `静态检查` / `单元测试` / `集成测试` / `真机验收` |
| 现在拦住 | 现在真正拦住它的测试名（必须能在仓库里搜到） |

只记**真实发生过**的问题（用户可见、或会导致数据/信任损失），不记"差点发生"。
如果某个事故至今没有对应测试，写"—"，那本身就是待办。

## 维护约定

- 修 bug 的 PR 如果属于"用户可见的错误承诺"，必须同时加一行台账与一条回归测试；
- 测试名改名时同步更新这张表（否则"现在拦住"会指向不存在的测试）；
- 超过 30 行的表格就该回头看看：是测试太弱，还是同一类错误在反复出现。
